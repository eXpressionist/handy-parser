# Handy Parser

Лёгкий мониторинг цен и других значений на веб-страницах с уведомлениями в Telegram.

**Статус: проектирование.** В репозитории находятся требования, результаты проверки источников, план реализации и примеры конфигурации. Приложение и Docker-образ ещё не реализованы. Команды установки в документации описывают целевой интерфейс первого релиза и пока не являются рабочей установкой.

## Задача

- Debian 13, VPS с 2 CPU и 2 ГБ RAM, около 800 МБ свободно; на сервере уже работают другие приложения.
- До 10 наблюдений, четыре проверки в сутки, возможность запуска вручную.
- URL и CSS-селекторы можно вводить вручную; для PSP предусмотрен встроенный обработчик API.
- Небольшая веб-панель: настройка, предпросмотр значения, статус и история.
- Telegram: старое и новое значение, ссылка; отдельные уведомления о длительной недоступности источника.
- Установка через Docker Compose, хранение данных вне контейнера.

## Выбранный подход

Go + SQLite. Один бинарный файл, два основных режима: `serve` для веб-панели и `check` для разовой проверки. Веб-панель работает отдельным небольшим контейнером. Таймер systemd на хосте четыре раза в сутки запускает временный контейнер `check`; после проверки он завершается и удаляется. Между проверками процесс парсера отсутствует. Docker Engine и веб-панель продолжают занимать память.

Chromium, Redis, отдельный сервер БД и постоянно работающий Telegram-бот в первой версии не требуются. Изменение наблюдения и кнопка ручной проверки доступны в панели. Ручная проверка использует то же ядро проверки и блокировку, что и команда `check`.

## Проверенные источники

| Источник | Метод | Результат проверки 16.09.2026 |
| --- | --- | --- |
| GPC | HTTP GET, `meta[name="product:price:amount"]`, атрибут `content` | 137.95 GEL, совпало с браузером |
| PSP | Публичный GraphQL: `urlResolver` → `productsByID` | 89.67 GEL, обычная цена 137.95 GEL; совпало с браузером |

Это снимок результатов с компьютера разработчика, а не обещание текущей цены. Доступность с IP VPS необходимо проверить перед первым релизом.

## Порядок работы

1. Реализовать ядро проверки, хранение состояния и обработчики сайтов.
2. Добавить Telegram и лёгкую панель настройки.
3. Собрать Docker-образ, проверить контейнеры и таймер на Debian 13.
4. Измерить память и выпустить первый тег с образом в GHCR.

Подробные задачи и проверки перечислены в [плане реализации](docs/IMPLEMENTATION_PLAN.md). Публичность репозитория не означает выпуск продукта: рабочая установка появится после завершения этапа релиза.
