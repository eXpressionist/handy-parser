# Архитектура и требования

Статус: спецификация первой версии. Описанное поведение ещё предстоит реализовать.

## 1. Объём первой версии

Однопользовательское приложение для максимум 10 наблюдений. Наблюдение задаёт страницу, способ извлечения, тип значения и правило уведомления. Общее расписание — четыре раза в сутки. Панель позволяет приостанавливать наблюдения, проверять селектор, запускать проверку и смотреть историю.

В первой версии не нужны визуальный выбор элемента, браузерный движок, авторизация на целевых сайтах, CAPTCHA, прокси-пулы, распределённые очереди и управление несколькими пользователями. Новые сайты сначала проверяются на возможность HTTP-парсинга; обязательное выполнение JavaScript требует отдельного решения.

## 2. Процессы и установка

```text
Браузер пользователя → SSH-туннель → контейнер serve ─┐
                                                    ├→ SQLite /data
systemd.timer → временный контейнер check ────────────┘
                         ↓
                  GPC HTML / PSP API
                         ↓
                    Telegram API
```

- Один образ и один бинарный файл. `serve` и `check` используют общие пакеты.
- Панель постоянно работает; проверки по расписанию выполняет отдельный временный контейнер.
- `check` не имеет опубликованных портов и завершается после ограниченной серии попыток.
- Планировщик находится на Debian-хосте. Установка приложения через Docker не требует переносить systemd внутрь контейнера.
- Параллельные проверки из панели и контейнера исключаются общей неблокирующей файловой блокировкой `/data/check.lock`. Файл может сохраняться, ОС снимает блокировку при завершении процесса. Занятая блокировка означает «проверка уже выполняется».
- Изменения настроек допустимы во время загрузки страницы: транзакции короткие, запросы к сайтам выполняются вне транзакции. Перед фиксацией результата проверяется версия настройки; результат устаревшей версии отбрасывается.

## 3. Технологии

- Go, стандартные `net/http`, `html/template`, `context`, `log/slog`.
- CSS/HTML: goquery; зависимости и Go toolchain фиксируются при реализации.
- SQLite через совместимый с `CGO_ENABLED=0` драйвер, например modernc.org/sqlite. Перед выбором проверить размер, память и актуальную совместимость.
- Серверные HTML-шаблоны, небольшой локальный CSS и минимальный JavaScript. Сборка интерфейса на VPS не требуется.
- Денежные значения: десятичный разбор без сравнения float64; для GEL хранить целое количество тетри и валюту. Для произвольного числа — нормализованную десятичную строку.

## 4. Извлечение значений

### Универсальный HTML

Параметры: URL, CSS-селектор, текст либо имя атрибута, тип `price`/`text`, валюта и правила десятичного разделителя для цены. Успех — ровно одно подходящее непустое значение. Ноль или несколько совпадений дают диагностическую ошибку. Несколько цен нельзя молча сводить к первой.

Предпросмотр показывает исходное значение, нормализованный результат, число совпадений и понятную ошибку. HTML сайта отображается как текст и не исполняется в панели.

Профиль GPC: `meta[name="product:price:amount"]`, атрибут `content`; валюта из `meta[name="product:price:currency"]`. Это остаётся обычным HTML-наблюдением с готовыми настройками.

### PSP

Пользователь вводит URL. Обработчик проверяет домен, определяет ID через `urlResolver`, показывает название и SKU, сохраняет их после подтверждения формы. Проверка получает `productsByID` и поле `price_range.maximum_price.final_price.value`. Обычная цена и stock_status сохраняются как дополнительные сведения.

Запросы: `https://app.psp.ge/graphql`, язык `ka`, без cookies и пользовательской авторизации. GraphQL errors считаются ошибкой даже при HTTP 200. ID/SKU и корректность числового значения проверяются до сохранения. При недоступном ID повторно разрешить исходный URL один раз; смену SKU показать как ошибку соответствия товара.

PSP API — внутренний интерфейс публичного сайта, а не договор о стабильности. Изменение схемы может потребовать обновления обработчика. Произвольный GraphQL-код пользователь не вводит.

## 5. Данные

| Сущность | Основные поля |
| --- | --- |
| watches | id, name, url, extractor, selector, attribute, value_type, currency, adapter_config, enabled, rule, revision |
| watch_state | watch_id, last_value, last_success_at, last_check_at, last_error, consecutive_errors, error_alerted |
| changes | id, watch_id, old_value, new_value, currency, observed_at |
| runs / check_results | время, причина запуска, статус, HTTP-код, длительность, краткая ошибка |
| outbox | тип события, снимок текста/ссылки, статус отправки, число попыток, следующая попытка |
| schema_migrations | версия схемы |

SQLite: WAL, foreign_keys, busy_timeout, короткие транзакции и ограниченное число соединений. Изменение состояния, запись истории и постановка сообщения в outbox выполняются одной транзакцией. Токен Telegram и пароль панели в БД не хранятся.

Хранение по умолчанию: изменения 365 дней, результаты проверок 30 дней, доставленные события 30 дней. Неотправленные события не удаляются автоматически; превышение лимита очереди отражается в статусе здоровья. Ограничить длину значения и ошибки. Тела страниц и полные HTTP-заголовки по умолчанию не сохранять.

## 6. Сравнение и Telegram

1. Первое успешное значение формирует исходную точку, без уведомления об изменении.
2. Форматирование пробелов, валюты и десятичного разделителя нормализуется по настройке.
3. Правила: любое изменение; только снижение; пересечение заданного порога сверху вниз. Для текста доступно только изменение.
4. История фиксирует все изменения, даже если правило не требует уведомления.
5. Пустое значение, timeout, HTTP-ошибка, неоднозначный селектор и ошибка API не заменяют последнее успешное значение.
6. После трёх последовательных ошибок — один алерт; после восстановления — одно сообщение. При четырёх проверках в день это намеренно не мгновенная диагностика.
7. Сообщение: название, старое → новое значение, валюта, разница для цены, время, ссылка.
8. Telegram 429 учитывает retry_after в пределах бюджета запуска; сетевые/5xx ошибки получают ограниченные повторы. Остальное остаётся в outbox до следующего запуска или ручной отправки.

Отправка гарантируется как минимум один раз при восстановлении сервиса, а не строго однократно: при принятом Telegram сообщении и потерянном ответе возможен дубль. Добавлять стабильный ID события в служебные данные и исключать повторную постановку одной записи изменения. Ошибка Telegram не отменяет сохранение новой цены.

## 7. Ресурсы и ограничения

Это проектные цели, а не результаты измерений:

| Параметр | Начальная настройка |
| --- | --- |
| Одновременные загрузки | 1 |
| Пауза между запросами одному сайту | Не менее 2 секунд |
| Таймаут запроса | 20 секунд |
| Общий бюджет check | 4 минуты, включая повторы и отправку |
| Распакованное тело ответа | До 2 МиБ |
| Перенаправления | До 3, с повторной проверкой адреса |
| Лимит контейнера web | 96 МиБ, 0.5 CPU |
| Лимит контейнера check | 192 МиБ, 0.5 CPU |
| Цель памяти панели в покое | RSS до 50 МиБ |
| Цель пика check | До 128 МиБ на согласованных 10 страницах |

На процесс `serve` распространяется лимит 96 МиБ и при ручной проверке. Если измерения покажут, что ручная проверка не укладывается, пересмотреть бюджет или механизм запуска до выпуска. Нельзя выдавать лимит контейнера за фактическое потребление. Замерять и вклад Docker Engine/containerd, если их ранее не было на VPS.

Время между проверками CPU приложения должно быть близко к нулю. Браузерные процессы не допускаются в базовом образе.

## 8. Доступ и секреты

- Панель публикуется только на `127.0.0.1:8080`; штатный доступ — SSH-туннель. Для внешнего доступа нужен отдельный HTTPS reverse proxy.
- Пароль администратора обязателен, читается из файла; логин с HttpOnly/SameSite cookie, CSRF-защита для изменений, ограничение попыток входа. Secure cookie включается в HTTPS-режиме.
- Контейнеры работают под UID/GID 10001, с read-only rootfs, writable `/data` и `/tmp`, без дополнительных capabilities и без Docker socket.
- URL только HTTP(S), без встроенных логинов. Запретить loopback, link-local, private/reserved IP и обращения к metadata endpoints; проверять DNS, адрес фактического соединения и каждый redirect, включая IPv6. Это требуется для формы произвольного URL.
- Секреты не попадают в URL страницы, логи, экспорт, Git или образ. Ошибки Telegram редактируются, чтобы скрыть токен из адреса API.

## 9. Контракт команд первого релиза

| Команда | Поведение |
| --- | --- |
| `serve` | Панель на 0.0.0.0:8080 внутри контейнера; корректное завершение по SIGTERM |
| `check` | Все активные наблюдения, outbox, итоговый отчёт; выход по окончании |
| `migrate` | Применение схемы явно, до запуска обновлённой панели |
| `healthcheck` | Локальная проверка готовности HTTP и БД для Docker HEALTHCHECK |

`check`: код 0 — серия завершена без ошибок либо блокировка занята; код 1 — ошибки отдельных источников/доставки; код 2 — конфигурация/БД/непредвиденная ошибка. Пропуск из-за блокировки явно журналируется. Логи JSON в stdout/stderr с ротацией на стороне Docker.
