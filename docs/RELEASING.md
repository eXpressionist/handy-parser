# GitHub и выпуск продукта

## Репозиторий

Целевой публичный репозиторий: `eXpressionist/handy-parser`. Основная ветка `main`. На первом этапе публикуются документация, план и шаблоны; отсутствие рабочего приложения явно обозначено в README.

В репозиторий не входят токены, пароли, `.env`, локальные базы, логи, резервные копии и загруженные полные HTML/JavaScript сторонних сайтов. Research содержит только собственные заметки, запросы и небольшие публичные ответы товара.

Публичная доступность исходников сама по себе не выбирает лицензию. Решение о лицензировании принять отдельно до первого релиза; пока не добавлять лицензию от имени владельца автоматически.

## Разработка

- Каждая задача плана реализуется небольшой законченной веткой/PR.
- PR объясняет изменение поведения, способ проверки и ограничения.
- Обычные тесты используют фикстуры и локальные тестовые серверы; живые магазины не опрашиваются на каждом push.
- После реализации добавить CI: gofmt, go vet, тесты, сборка Linux amd64/arm64, проверка Compose и smoke test контейнера.
- Действия GitHub Actions закрепить по полным commit SHA. Проверки PR выполняются без секретов публикации, с минимальными правами.

## Docker-образы

Целевой адрес: `ghcr.io/expressionist/handy-parser`. Во всех ссылках на образ владелец в нижнем регистре. Основная ветка публикует изменяемый тестовый тег `edge`; версии `vX.Y.Z` публикуются по Git-тегам.

1. Multi-stage сборка: компилятор только на стадии build, небольшой non-root runtime с CA certificates.
2. Образ включает бинарник и ресурсы интерфейса, но не пользовательскую конфигурацию/БД/секреты.
3. Проверить поддержку linux/amd64 и linux/arm64 и отсутствие внешних runtime-зависимостей.
4. Публиковать по тегам `vX.Y.Z`; сохранять digest и метку исходного commit.
5. Использовать GitHub Actions GITHUB_TOKEN с `contents: read`, `packages: write` только в job публикации. Не добавлять персональный токен в workflow.
6. Добавить OCI-метку `org.opencontainers.image.source=https://github.com/eXpressionist/handy-parser`, чтобы связать пакет с репозиторием.
7. У первого пакета проверить видимость отдельно: публичный репозиторий не гарантирует публичность пакета GHCR. Перед выпуском проверить анонимный docker pull.

Никакого доступа к VPS в CI первой версии не требуется. Владелец обновляет сервер вручную по инструкции.

## Первый релиз v0.1.0

- Выполнены этапы 1–8 и итоговая приёмка из плана.
- Приложение реально устанавливается через документацию Docker на Debian 13.
- Подтверждены Telegram, GPC и PSP с VPS.
- Опубликованы измерения памяти в покое и при проверке; отдельно учтён Docker Engine.
- Проверены резервная копия и восстановление.
- Проверены таймер после reboot и уборка контейнера после timeout.
- Созданы тег, release notes, deploy-архив и контрольные суммы.
- Образ доступен по неизменяемой версии/digest; установка не требует сборки на VPS.
- README обновлён с фактическим статусом и рабочими командами.

После push тега workflow сначала публикует multi-arch образ, затем создаёт GitHub Release. В deploy-архиве Compose закрепляется за digest собранного образа, рядом публикуется файл SHA-256. Тег создаётся только после приёмки на Debian/VPS; для проверки упаковки без релиза CI использует фиктивную версию `v0.0.0-ci`.
